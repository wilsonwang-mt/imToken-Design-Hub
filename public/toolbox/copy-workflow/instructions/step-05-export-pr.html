Workflow / Step 05
STEP 05 — 核心步骤

导出 → 转换 → 提交 GitHub PR

从 Figma 导出定稿文案，转换为开发可用的 i18n 格式，通过 PR 提交到代码仓库

Designer — 负责执行
Phase A — Figma 导出

从 Figma 导出 Variable Collection

1

打开 Variable Importer/Exporter 插件

Figma → Plugins → Variable Importer/Exporter → 选择 Export 模式。

2

选择 "Copy" Collection → 逐个导出每个 Mode

选中 Copy Collection，分别导出 EN、ZH-Hans、ZH-Hant 三个 Mode 的 JSON 文件。导出格式为 DTCG（Design Tokens Community Group）标准。

Variable Importer/Exporter — Export Mode
Collection: Copy
Select mode to export:
EN ZH-Hans ZH-Hant
Export to JSON
3

得到三个 DTCG 格式的 JSON 文件

导出后你会得到：EN.tokens.json、ZH-Hans.tokens.json、ZH-Hant.tokens.json

↓
Phase B — 格式转换

运行 figma2i18n 脚本生成 dev-ready 文件

1

运行转换脚本

将三个 Figma 导出文件放在同一文件夹，运行转换脚本。脚本会自动完成 DTCG → i18n 格式转换，并与原有 i18n 文件合并（保留 code-managed 的长文本 key），生成 Changelog。

● Terminal — 运行转换脚本 
# 将 Figma 导出文件放在 exports/ 目录下
$ ls exports/
EN.tokens.json    ZH-Hans.tokens.json    ZH-Hant.tokens.json

# 运行转换脚本（需要指定原有 i18n 文件路径用于合并）
$ python3 figma2i18n.py \
    --exports exports/ \
    --baseline src/locales/en.json \
    --output dist/

3

Review Changelog 确认变更正确

打开 CHANGELOG 文件，逐条检查变更项。确认所有修改都符合 Step 04 的审查结论。

↓
Phase C — 提交 GitHub PR

通过 GitHub Web UI 创建 Pull Request

1

在 GitHub 仓库中创建新 Branch

进入项目仓库 → 点击 branch 下拉 → 输入新分支名称（如 copy/golden-season-update-0227）→ Create branch。

2

上传 i18n 文件覆盖原文件

在新分支上导航到 i18n 文件目录（如 src/locales/），点击 "Add file" → "Upload files"，将三个 JSON 文件拖入上传，替换原有文件。

3

创建 Pull Request

上传完成后，GitHub 会提示创建 PR。点击 "Compare & pull request"。

Open a pull request
copy: update Golden Season i18n (2026-02-27)
Create pull request
PR 规范：标题格式建议 copy: [描述] (日期)，便于开发在 commit history 中快速识别文案变更。正文中引用 Changelog 关键信息，让 Reviewer 无需打开文件就能了解变更范围。

➤ 本步骤产出物

一个包含 3 个 i18n JSON 文件 + 1 个 Changelog 的 GitHub Pull Request，等待开发 Review。
