STEP 06

Code Review & Merge

开发审查 PR，确认格式和 key 引用无误后合并到主分支

Developer — 负责执行 Designer — 响应反馈

开发 Review 检查清单

  • ✓ JSON 格式验证：文件是否为合法 JSON（无尾逗号、编码正确）
  • ✓ Key 完整性：是否有 key 被意外删除或新增（对比 Changelog）
  • ✓ 代码引用：新增/删除的 key 是否会影响代码中的 t('goldenSeason.xxx') 调用
  • ✓ 变量占位符：{amount}、{currency}、{date} 等占位符是否保留正确
  • ✓ HTML 标签：富文本 key 中的 HTML 标签是否完整闭合
  • ✓ 特殊字符：引号转义、Unicode 字符是否正确

Review 流程

1

查看 PR 的 Files Changed

在 GitHub PR 页面查看 diff，重点关注 key 的增删和值的变化是否符合 Changelog 描述。

Files changed (3)
src/locales/en.json
- "openPremiumBox": "You got a premium box!",
+ "openPremiumBox": "You got a mystery box!",
- "congratsYouGot": "Congrats, you got {amount} {currency}!",
+ "congratsYouGot": "You've received {amount} {currency}!",
src/locales/zh-Hans.json
- "premiumBoxesLeft": "剩余盲盒数量",
+ "premiumBoxesLeft": "盲盒余量",
2

如有问题 → 在 PR 中 Comment 反馈

发现格式错误或 key 冲突时，直接在 PR 的具体行上添加 Review Comment，@设计师修复。

3

Approve & Merge

确认无误后点击 "Approve"，然后 "Squash and merge" 合并到主分支。Merge 后 CI/CD 自动部署。

注意：如果开发发现有 key 被意外删除（Figma 导出不包含 code-managed 的 key），需要确认转换脚本是否正确合并了原有文件。这是最常见的问题来源。
最佳实践：在项目的 CI 中添加 i18n 文件校验步骤（如检查 JSON 合法性、key 引用完整性），可以在 PR 阶段自动发现问题，减少人工 Review 负担。
✓

文案已上线

PR 合并后，最新的三语文案通过 CI/CD 自动部署到生产环境。
从 Figma 定稿到代码上线，全程无需手动复制粘贴任何文案。
