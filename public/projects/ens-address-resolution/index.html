    Part 2 · Information Architecture

    地址解析组件的信息架构

    Tooltip 要表达的信息分为两部分：区域一是帮助用户评判这个地址风险的判断辅助信息（交易历史 / Warning / High risk），区域二是对用户输入的地址 / 域名解析出来的事实（Address info）。两部分性质不同，所以分区承载：区域一与区域二之间用一条分割线隔开；Warning / High risk 时区域二折叠进「More address info」；只有区域二时没有分割线。

    分割线以上

    区域一判断辅助信息

    帮助用户评判这个地址有没有风险的输入，与区域二的解析事实分开承载。等级由风控系统返回，体验层只区分 Info / Warning / High risk；L2 以上时不显示交易历史。

    • Transaction Record（交易历史）Tag = Info 时展示：标题「Transaction Record」+ 正文「You haven't transacted with this address before.」。无法检测是否有交易记录 → 不显示；检测到有交易记录 → 目前拿不到具体记录，也不显示（未来支持后同样在此区块显示）。Info
    • Warning可能存在风险，但未确认；标题 + 正文常显，区域二折叠。Warning
    • High risk明确存在风险；与 Warning 同一结构，只有输入框 Tag 的颜色升级。High risk
    分割线以下

    区域二地址解析信息（Address info）

    针对用户输入的地址 / 域名解析出来的事实，三类信息按下面的优先级在列表中排序：

    1. 优先级最高专项信息识别地址所属链类型（Cosmos / Osmosis，IBC 跨链）；地址状态（Polkadot / Kusama / Tron / Tezos 未激活地址、TON 反弹地址）
    2. 地址标记是否是地址本存储的地址；是否是用户当前某个钱包中的账户地址。两者同时命中时同时显示（不二选一），「已存于地址本」排在「我的钱包」之前；多数情况下不会既是又是
    3. ENS 正向 / 反向解析结果正向：域名 → 解析出的地址全文（等宽单行、首尾加重）；反向：地址 → 关联的单个域名
    附加规则

    折叠与唤起

    风险类信息与地址解析信息同时存在时的展示规则。

    • Tag = Warning / High risk → 区域二默认折叠Tooltip 只常显风险条目，地址解析信息收进「More address info (N)」，可反复展开 / 收起；交易历史不显示。
    • Tag = Warning / High risk → 自动唤起后不自动消失用户点击空白区域、或与其他控件交互时才收起。
    • Tag = Info → 不折叠区域一（若有 Transaction Record）与区域二并列，中间一条分割线；区域二为空或区域一为空时没有分割线；自动唤起后 4s 收起。

    组件按 S1 极简版原样渲染；右侧色条标出对应区域，文字说明其规则。
