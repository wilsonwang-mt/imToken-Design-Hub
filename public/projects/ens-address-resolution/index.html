Part 2 · Information Architecture

地址解析组件的信息架构

Tooltip 要表达的信息分为两部分：区域一是帮助用户评判这个地址风险的判断辅助信息（交易历史 / Warning / High risk），区域二是对用户输入的地址 / 域名解析出来的事实（Address info）。两部分性质不同，所以分区承载：区域一与区域二之间用一条分割线隔开；Warning / High risk 时区域二折叠进「More address info」；只有区域二时没有分割线。

分割线以上

区域一判断辅助信息

帮助用户评判这个地址有没有风险的输入，与区域二的解析事实分开承载。等级由风控系统返回，体验层只区分 Info / Warning / High risk；Warning / High risk 时不显示交易历史。区域一条目不带标题（Tag 已说明等级）；Warning / High risk 条目左侧有 3px 色条（橙 / 红）；Transaction Record 无色条、无标题，纯正文（色条 ⏳ 探索中，是「popover 内无彩色」原则的例外）。色条的另一个好处：多条 Warning 同时命中时上下排列即可，色条引导逐条阅读；「标题 + 副标题」方式在多条 warning 时标题会重复，难以处理。

  • Transaction Record（交易历史）Tag = Info 时展示：纯正文「You haven't transacted with this address before.」，无标题、无色条。无法检测是否有交易记录 → 不显示；检测到有交易记录 → 目前拿不到具体记录，也不显示（未来支持后同样在此区块显示）。Info
  • Warning可能存在风险，但未确认；橙色色条 + 正文常显，区域二折叠。Warning
  • High risk明确存在风险；与 Warning 同一结构，色条与输入框 Tag 一起升级为红色。High risk
分割线以下

区域二地址解析信息（Address info）

针对用户输入的地址 / 域名解析出来的事实，三类信息按下面的优先级在列表中排序：

  1. 优先级最高专项信息识别 · 特定网络的地址解析label 标识这是哪个网络的地址：Osmosis address（IBC 跨链转账）/ Tron address（尚未激活，额外消耗 TRX 激活）/ TON bounceable address（转账失败自动退回）…；正文写该网络的具体说明。同一个地址不可能来自不同网络，所以这类条目只会出现一条，并排在 Address info 最前
  2. 地址标记是否是地址本存储的地址；是否是用户当前某个钱包中的账户地址。两者同时命中时同时显示（不二选一），「已存于地址本」排在「我的钱包」之前；多数情况下不会既是又是
  3. ENS 正向 / 反向解析结果正向：域名 → 解析出的地址全文（与其他内容同字体字号，可换行）；反向：地址 → 关联的单个域名
附加规则

折叠与唤起

风险类信息与地址解析信息同时存在时的展示规则。

  • Tag = Warning / High risk → 区域二默认折叠Tooltip 只常显风险条目，地址解析信息收进「More address info (N)」：点击展开，展开后不可收起；看完点空白处关闭；交易历史不显示。
  • Tag = Warning / High risk → 自动唤起后不自动消失用户点击空白区域、或与其他控件交互时才收起。
  • Tag = Info → 不折叠区域一（若有 Transaction Record）与区域二并列，中间一条分割线；区域二为空或区域一为空时没有分割线；自动唤起后 4s 收起。

组件解剖：两个信息区，各自承载一个信息维度

区域一帮助用户识别风险（Transaction Record / Warning / High risk；Warning / High risk 左侧色条引导阅读）；区域二帮助用户理解地址解析出来的 facts（专项信息 → 地址标记 → ENS）。组件按 S1 极简版原样渲染，右侧色条标出对应区域。

v2.3 · 专项信息

专项信息文案优化 · 线上 → 定稿

区域二 ① 三条专项信息的正文改写。label 已标明网络，正文只说对用户的后果；左列为线上文案（PM 提供），右列为定稿。

  • 线上 · TronThis address is not activated. It will cost {{num}} TRX to activate the address→定稿 · Tron addressNot activated yet. An extra {{num}} TRX will be spent to activate it.
    label 已标明网络 → 正文不再重复「This address is…」；先说后果（额外消耗的费用）；cost → extra … spent 更准确（是本次转账额外的支出，不是地址的价格）；一句话 ≤ 2 行。
  • 线上 · TONThis is a bounceable address and supports normal transfers. If an error occurs, the funds will be automatically returned to you→定稿 · TON bounceable addressTransfers work as usual. If the transfer fails, funds are returned to you automatically.
    label 已标明「bounceable」→ 正文不再重复「This is a bounceable address」；先说后果（可正常转、失败会退款）；error → fails 更准确（用户关心的是转账失败，不是「错误」）；一句话 ≤ 2 行。
  • 线上 · IBCThe receive address is in {{chainName}} address format, and the transfer will be executed as an IBC cross-chain transfer→定稿 · {chainName} address（IBC 场景 = Osmosis）Funds will be sent via IBC cross-chain transfer.
    label「{chainName} address」已标明收款地址的格式 → 正文不再重复「The receive address is in … format」；直接说怎么发（走 IBC 跨链）；一句话 ≤ 2 行。
