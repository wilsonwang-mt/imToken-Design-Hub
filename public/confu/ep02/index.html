③ 写成规则：你给参照和三个回答，AI 写出九条规则

你提供的

参照：04 Compound
心情：有点紧张
像：不说废话的私人银行家
绝不能像：赌场、AI 模板

AI 写的 · style-lock.md（你不用读）
1 锚点 Compound · Wise · UI 3.0
2 形状 圆角 12–16 · 线多于面
3 字体 Jakarta 600 · Inter · Mono 数字
4 色彩 #007FFF 只给主操作 · #A78BFA 只给 Agent
5 密度 一屏只有一个决定
6 层次 字号 + 1px 边框 · 阴影只给浮层
7 动效 150/240/360/500ms · 只在状态变化时动
8 图像 无插画人物 · Lucide 1.5px
9 禁止 渐变按钮 · emoji · 装饰 3D · 标语 …
少写一行，AI 就会自己补默认值，紫到蓝的渐变就是这么来的。
你的判断：只需读这三句（示例复述）

「层级靠尺寸与留白，不靠颜色。」
「整屏只有一个蓝色，给最重要的那个动作。」
「数字最大，其余都退后。」
像那个人就继续，不像就换一张。

PART 1 · RECAP

同一句需求，两种写法

常见写法
帮我做一个高级、有科技感的钱包首页。
  • 没说用户在什么时刻、带着什么心情打开它
  • 「高级」可以是十几种样子，AI 只能挑最常见的那种
  • 没说不要像什么，默认风格就会溜进来
  • 一句话说完就开始生成，没有确认的机会
让 AI 知道你要什么
做一个钱包首页。用户在转账前打开它，有点紧张，最想确认钱还在、最近一笔到了没有。
参照参照 Compound 的会员页（附截图）：学它用字号和留白分层级，不学它的衬线字体。
像谁它应该像一个不说废话的私人银行家；绝不能像赌场，也不能像 AI 模板。
规则风格规则见 style-lock.md。动手前，先用三句话复述这个风格的核心，等我确认。
  • 一个真实参照，并且说清学什么、不学什么
  • 一句「像谁 / 不像谁」，排除掉一整类风格
  • 规则写成数值，放在文件里，每次生成都照着它
  • 先复述，确认了再动手

回顾：让 AI 少猜，靠的是一份写全的 Brief

刚才看到的1Brief 先写好，agent 只负责翻译成画布2画布上直接改字、切 Tweak3一份设计按使用者拆成三种交付
✕ 常见写法AI 只能猜

帮我给「我是主理人」活动做一个好看的官网，风格现代一点，要有科技感。

✓ 更专业的写法 · Brief 骨架
角色你是资深产品设计师兼前端工程师，用 Claude Design 产出「我是主理人」活动官网的可交互画布。
口径以 All Hands deck 第 07–25 页为准：这不是黑客松，是主理人选拔。
输入deck 全文、现站走查 27 条、imToken Web DS 的 token。三者冲突时以 deck 为准。
不可妥协文案逐字来自 deck，不许润色；首页十一段顺序固定，不许增删；没定的日期留空；颜色、字号、圆角只用 DS token；禁止 emoji 图标、渐变铺底、左侧色条卡片。
规格三个画板：桌面 1440 可交互整站、手机 390、主视觉 1920×1080。每段按「段落 | 现站状态 | 你要做的」写成表格。
验收1440 和 390 各截图，逐项点交互，console 零报错，然后再发布。
回报链接；每段做了什么；哪些是示例或假设；和 Brief 不一致的地方。

一份 Brief 要写全这五样

  • 口径：以哪份文档为准，冲突时听谁的
  • 文案：逐字给出，不让它自己写
  • 视觉规则：token、唯一的突破点、禁止项
  • 结构：段落顺序写死，不许增删
  • 验收：截图宽度、要点的交互、console

在 Claude Design 里这样改

  • 大方向在对话里改；某个组件用行内评论；改字、挪位置直接在画布上动
  • 反馈要能执行：「表单字段间距收到 8px」比「看起来不太对」有用
  • 换方向之前，先让它把当前版本存下来
  • 只把贯穿全站的变量做成 Tweak，比如强调色；文案写死在页面里

一份 Primer 贴在每次对话最前面，后面接单屏需求。Primer 叠了三层：v2（产品、参照、双主题 token）、Supplement、Visual Refresh（Azure 主色、玻璃材质、动效 < 250ms）。

按 Primer 用法整理的模板
[Primer 全文] + [本屏需求]。每屏交 4 个变体：手机 / 桌面 × 浅色 / 深色；组件里只用语义 token；一屏一个对话，跑两轮，第二轮继续带着 Primer。
03

产出了什么

  • app/：15 个 JSX 组件 + tokens.css（双主题语义 token）+ data.js
  • WC2026 HyperAgent - Offline.html：5.9 MB 离线单文件，双击就能看
  • Audit & Plan：它自己查出 18 条问题，按 P0–P3 分四期修
  • Data Interface Spec：实体、接口、原型字段到正式接口的对照
04

用的时候要注意

  • 原型里的字段名就是接口契约：写进文档，工程照用，UI 不用返工
  • 导出前先清理：没被引用的旧文件会误导对方的 AI，先移到 archive
  • Primer 和绑定的设计系统冲突时，它会自己挑一个；审计把这条列成待决问题，要你拍板
  • 截图看不出的问题要让它实际去点：主题切换后文字颜色残留、手机上横向溢出，都是点过才发现的

回顾：规则写成 Primer 反复用，交出去之前先让它自审

✕ 常见写法AI 只能猜

做一个世界杯预测产品的首页，深色，有科技感，要高级。

✓ 更专业的写法 · Primer + 单屏需求
产品WC2026 HyperAgent：只面向 imToken 老用户的封闭社区赛。AI 找出定价偏差的市场并解释理由；Polymarket 结算，每一笔都由用户自己签名。
要像Linear 的专注和密度、Apple Sports 的赛程卡片、Polymarket 的交易场感。
不要像DraftKings 式的赌场感和假紧迫感；霓虹赛博朋克；满屏彩虹渐变。
Token语义命名，浅色、深色各一套：--bg、--card、--ink、--brand（#007FFF）、--yes、--no。组件里不写死色值。
响应式手机优先，390、平板到 1440 都要顺畅可用。
本屏Match 详情和 AI 对话：连接钱包、AI 判断、下注预览、签名状态，都以卡片形式嵌在对话里。
交付4 个变体：mobile-light、mobile-dark、desktop-light、desktop-dark。

一份 Primer 要写全这五样

  • 产品和受众：一句话说清给谁用、解决什么
  • 正反参照：要像谁、不要像谁，各 3–5 个，比形容词准
  • 语义 token：双主题，按用途命名，不按颜色命名
  • 字体、动效、响应式：写成数值，不写感觉
  • 升级时写明覆盖哪一条：例如 Visual Refresh 注明覆盖 v2 §4

交给工程之前

  • 先让它自审：每页在浅色、深色、桌面、手机下都实际点一遍（按钮复制这段 Prompt）
  • 让它写数据接口说明：字段名就用前端现在绑定的名字
  • 导出前清掉没被引用的旧文件；交给对方时附一句「先读 README 和接口说明」
  • 有代码库的团队，可以在 Claude Code 里用 /design-sync 把真实组件和 token 同步进 Claude Design

TAKEAWAY 3 / 5

它做不好的，和必须你来做的

工具的限制 · 2026-09 预览版
  • 画板之间状态不共享，桌面和手机的交互各管各的
  • PNG、PDF 导出不嵌 Google Fonts，中文会回退成系统字体
  • 画布文件不能直接分发，要先转成独立 HTML
  • 两人同时编辑会冲突，适合一人主编
它会犯的错
  • 自信地写错：示例数据、猜的日期，写得和事实一样
  • 热心地补充：加上你没要的段落、动效和颜色
  • 规则冲突时自己挑一个：项目 2 的 Primer 和设计系统打架，它先按自己的判断做，审计时才列出来
  • 越改越偏：改到第五轮，颜色悄悄多了两种
必须你来做的
  • 判断这个页面到底要讲什么
  • 在几个都画得出来的方向里选一个
  • 决定哪些地方不改，并说得出理由
  • 没定的信息留空，不让它编
  • 品牌资产宁可绕路去拿原图，也不让它重画
什么时候别用它 正式物料、高清导出 → Figma 要直接上线的代码 → Claude Code 多人同时编辑 → Figma
TAKEAWAY 4 / 5

明天就能用的起手 Prompt：七段结构

三个项目的 Prompt 长短不一，结构都是这七段。第 ⑤ 段最长，也最值得花时间。

①角色你是谁
②背景这件事是什么、给谁看、以哪份文档为准
③输入你会拿到什么，冲突时以谁为准
④不可妥协3–6 条硬规则
⑤规格逐屏写，用表格，不用段落
⑥验收截图、点交互、console
⑦回报改了什么、哪些是假设、偏差

「不要做的事」写成清单，它会照做；「适当发挥」这种话，每次理解都不一样。

起手模板 · 七段
① 角色：你是资深产品设计师兼前端工程师。 ② 背景：[这件事是什么、为什么做、给谁看；以哪份文档为准] ③ 输入：[你会拿到哪些材料，每份怎么用；互相冲突时以谁为准] ④ 不可妥协：[3–6 条硬规则，例如：文案逐字使用，不许润色；没定的信息留空，不许编；颜色、字号、圆角只用设计系统里的值] ⑤ 规格：[逐屏 / 逐段 / 逐个交互写清楚，用表格：段落 | 现状 | 你要做的] ⑥ 验收：[在 390 和 1440 两个宽度截图，逐项点交互，console 零报错] ⑦ 回报：改了什么；哪些是示例或假设；和要求的偏差；没完成的事。 不要做的事：[清单，例如：不要新增我没列的段落；不要换字体；不要加我没要的动效]

PART 03 · THE LOOP

给 AI 建立一套 Loop

把一个任务拆给几个 agent，
每一轮用证据决定前进，还是退回。

BRIEF → IA → EXPLORE → AUDIT → REFINE → RELEASE CHECK · ≈ 8 MIN
WHY A LOOP

一个 AI 从头做到尾，为什么磨不出好东西

常见做法会发生什么改成
01

自己写，自己查

同一个对话会替自己辩护，问题永远「差不多解决了」
审查另起一个没参与制作的 agent，只读、只写报告
02

交接只靠长聊天

上一轮的假设被当成事实，已经否决的方向又回来了
维护一份任务包：版本、规则、决定、问题、未验项；接手先复述
03

审查只给一句「还不够高级」

真正的阻断被平均分盖住，查过的和没查的混在一起
每条问题写位置、复现步骤、证据和复查方法，先处理阻断
04

只说「继续优化」

额度花完，第二天仍不知道哪一版能交
每轮只改一个主要问题；写好停止条件，到了就停
6 STAGES · EVIDENCE DECIDES THE NEXT STEP

六个阶段，审查结果决定退回哪一步

01 · BRIEF

定任务

用户在什么时刻要做哪个决定？怎样算完成？
交出来一页 Brief：任务、必须保留的、成功和失败条件
02 · IA

信息架构

每一步要知道什么、决定什么，出错回到哪？
交出来对象与流程图，加一张状态—内容表
03 · EXPLORE

探索与实现

哪个方向更适合这个任务？它牺牲了什么？
交出来两个同条件方向，选一个，做通一条能运行的路径
04 · AUDIT

独立审查

哪些问题有证据，最妨碍用户完成任务？
交出来可定位的问题单和证据，查过和没查的分开写
05 · REFINE

修订与回归

这次最小的改动解决什么？会影响哪里？
交出来可回退的修改版，同条件前后对照，再复查一遍
06 · RELEASE

上线前检查

这个版本在什么条件下能兑现承诺？
交出来交付结论：通过什么、被什么挡住、什么还没验
审查之后，下一步去哪不是一律重来，也不是一直往前
核心任务失败先由审查定位原因：结构错了回信息架构，实现问题交给修订，环境受阻就标「未验」 → 04 定位
信息结构不成立回到信息架构，把约定改好，再探索和实现 → 02
局部视觉问题按问题编号修订，在同样条件下前后对照 → 05
证据不足补实际操作、测量或用户观察；再问一遍模型不算证据 → 04 补证据
本轮门槛满足所有关键检查都有当前版本的证据，进入上线前检查 → 06
3 AGENTS TO START

三个 agent 就能起步：一人定，一个做，一个查

负责人ORCHESTRATOR · 通常是你

定任务和验收，分配边界，做取舍，决定下一轮做什么、什么时候结束。Brief、任务分派、决定和交接记录

制作IA · DESIGNER · BUILDER

先理清对象和状态，再出两个方向，选定后做通一条能运行的路径。分配给它的画板、代码和规格

独立审查AUDITOR · RELEASE QA

按任务、体验、界面、无障碍逐项查，给出可定位的问题和复查办法，不替自己做的东西背书。审查报告和证据，对作品只读

任务变大再拆开：制作拆成信息架构、设计、实现；审查拆成审查和上线检查，一共六种职责。
它们之间只传这六份文件
BRIEF.md用户、任务、范围、失败的代价
IA.md + STATES.md对象、导航、主路径、关键状态
REFERENCE-LOCK.md选定的方向、组件规则和禁区
ACCEPTANCE.md动手前约定的通过条件和证据要求
AUDIT.md + EVIDENCE/问题编号、严重度、复现和截图
DECISIONS.md + HANDOFF.md取舍、当前版本、下一轮交接
每次交接版本 / 本轮目标 / 读了哪些输入 / 改了什么 / 产物在哪 / 验证过什么 / 还没验什么 / 下一个 agent 做什么
规则同一个文件，同一时间只有一个人写；审查者只读，只写报告。
EVIDENCE · STOP RULES

审查要有证据，也要知道什么时候停

① 问题分四级，先修阻断

每条问题都要能复现

P0
会造成不可接受的损失或关键错误
P1
挡住核心任务，或造成重大误解
P2
局部质量问题
P3
可选的打磨
每条写：位置、复现步骤、证据、对用户的影响、最小修改、怎么复查。
② 证据的边界

这些都不算「通过」

  • 截图证明不了键盘、读屏、数据保存和出错恢复
  • 自动扫描零报错，不等于体验没问题
  • 几个 AI 都说好，可能只是重复同一个推断
  • 让 AI 扮演用户是检查线索，不是用户测试
  • 没有实际运行的检查，一律写「未验」
③ 停止条件

写在第一轮之前

  • 每轮只改一个主要问题，最多三项具体改动
  • 连续两轮同类改动没有改善：回去检查假设
  • 三轮后仍有 P0 / P1：停止交付承诺，交出阻断证据和下一步
  • 轮数用完，不等于可以发布

案例：UI 3.0 · Portfolio 页面 · 2026.07
PROBLEM

你一直在聊，它一直在猜

01

需求散在聊天记录里

「上面说过了，还是按那个来」
每轮都要重说一遍；换一个对话，前面的都丢了
02

反馈只有感觉，没有原因

「不太对，再高级一点」
AI 换个颜色、换个措辞，结构一点没动
03

目标是「好看」

「把顶部做得好看一点」
没法判断改没改好，只能凭感觉来回拉扯
04

一条一条提修改意见

「这个格子改大一点」
修好这里，别处又坏；下一轮它还可能悄悄改回去
SOLUTION · 5 WAYS TO WRITE

从聊天，换成写需求：五个写法

01

写一份唯一需求源

分三层：硬约束不能动；起点假设可以挑战，但要先问你；开放探索区交给它发挥。

例「这份文档是你唯一的需求来源。」
对应 01
02

目标写成能判断的问题

不写「好看」，写「用户 10 秒内要答出哪几个问题」。评审从此有了尺子。

例有什么 / 怎么分布 / AI 看到了什么 / 要做什么
对应 03
03

发散给它，裁决留给你

有两个以上可行解就做截图并排让你选。每次裁决编号，之后不许改回。

例「E1 选方案 B，记为 D3。」
对应 04
04

否决要逐字，说清为什么

把你的感受原话说出来，再让它总结成「不许再犯」写进需求源。

例「先重想，不要在原方案上换措辞。」
对应 02
05

给原则，不给修改意见

一个现象，写成对所有页面都生效的原则，再让它逐一检查。

例「不能一格很满、五格很空。」
对应 02 · 04
你提供判断，AI 提供产能。你的话越少越重，它放大出来的工作就越准

① 07-07 · 我的否决原话

「色带的可读性本身不好……收起后的状态就非常缺乏可识别性……点击色带页面滚动到不同的位置感觉很乱……你没有进行深度思考，也没有实现大胆突破，而是简单地 follow 色带这个死板的 idea。」

② AI 写进需求源的三条「不许再犯」
  • 比例条这种形态先天有缺陷：12px 高，占 2% 的资产只剩一粒碎屑
  • 抽象到最少，不等于好用
  • 点一下就跳到别处，打断了用户的心智模型
③ 下一轮三个方案 PK，它们成了评审的绊线

胜出的方案理由很具体：用户要答的四个问题，在同一行里从左到右全部有答案。

TEMPLATES · COPY & GO

两个模板：开题写一次，反馈随时用

模板 A · 唯一需求源开题时写一次，之后只改不重写
【开题时写一次：唯一需求源】 这份文档是你唯一的需求来源，分三层：硬约束不能动；起点假设可以挑战，但要先问我；开放探索区交给你发挥。 一、背景（30 秒版）：[产品是什么、给谁用、这次要解决什么] 二、硬约束（不可协商）：[设计规范 / 品牌规则 / 这次的禁令，例如不出现链名、数据不许改] 三、起点假设（可以挑战）：[当前方案的基线]。想改动时，先写「改什么、为什么」，等我确认；每次确认编号 D1、D2……之后不许悄悄改回。 四、开放探索区（交给你）：E1 [问题]；E2 [问题]……每项先给方案和理由，再动手；有两个以上可行解时，做成截图并排让我选。 五、成功标准：用户 [10] 秒内要能回答这几个问题：[问题 1] / [问题 2] / [问题 3] / [问题 4] 六、走查用户：[画像 A：是谁、最常做什么] / [画像 B] / [画像 C]。每一版都要过这三个人。 每轮结束写一份 NOTES：你替我做了哪些决定，哪些需要我推翻。
模板 B · 反馈句式想说「再高级一点」之前，先挑一句
【随时给反馈：四种句式】 否决：这一版我不接受。[逐字说：哪里、给你什么感觉、为什么]。先把它总结成三条「不许再犯」写进需求源，再重新想；不要在原方案上换措辞。 裁决：E[n] 选 [方案 X]，因为 [理由]。败方删掉，对比截图留档，记为 D[n]，之后不许改回。 原则：[现象] 不只是这一处的问题。把它写成一条对所有 [卡片 / 页面] 都生效的原则：[原则]。然后逐一检查现有每一处。 参考：这是 [竞品] 的截图。不要照抄，先分析它解决了什么问题、我们缺的是哪一层，再给方案。
