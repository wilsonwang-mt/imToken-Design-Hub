# 多Agent设计质量Loop：方法与模板

2026-09-24。配套交互教材：[index.html](index.html)。本方法以可验证的用户任务与质量门槛为目标，不承诺自动达到某个审美等级。

## 一、怎样组织一轮

### Brief｜先确定这次要帮谁完成什么

用户在什么时刻，需要做哪个决定；怎样才算完成？

输入：原始Idea、目标用户与使用情境；已有有效行为、合成数据与不可改的规则；本轮时间、工具能力、可修改范围

1. 写一页体验约定：起点、核心决定、成功结果，以及失败会付出的代价。
2. 把事实、假设和未知分开；确认11:00预约不动，交通为教学估算，本轮不接真实服务。
3. 选择一条最小路径和可观察的验收条件，为每份产物指定唯一写入者。

产物：一页Brief：用户任务、保留项、范围、成功与失败条件、实际能力、负责人和版本。所有Agent使用同一版。

通过条件：其他成员能复述相同目标与保留项；核心数据无矛盾；“能比较、确认、看懂结果并撤销”有对应检查办法。会改变方向的未知尚未解决时，先缩小范围或补证据。

常见坑：把“做一个世界级旅行App”当任务，生成许多页面，却没有约定用户必须完成的决定。

### IA｜先安排对象、入口和信息顺序

用户每走一步，需要知道什么、决定什么，出错后回到哪里？

输入：已对齐的Brief与当前产品基线；地点、行程、预约、冲突和调整方案的数据；主路径、异常状态及现有组件规则

1. 列清核心对象及关系：地点进入行程，移动与缓冲影响预约，调整必须保留锁定项。
2. 画出收藏→草案→冲突→比较→确认→结果→撤销；标记两日入口、返回位置、每步内容层级。
3. 补齐空数据、取消、保存失败和恢复；为每步写明触发、可见事实、动作与数据变化。

产物：一张对象与流程图，加状态—内容表。表中包含导航、主次信息、按钮含义、数据何时改变、失败如何恢复。

通过条件：每个决定所需信息都能在动作之前找到；取消不更改草案，确认后有结果，撤销有明确恢复点；入口和去路无断点。结构有冲突时不进入视觉制作。

常见坑：把IA只做成菜单或站点地图，漏掉确认时机、状态变化、信息先后与失败出口。

### Explore｜比较方向，选定后做通一条路径

哪一种结构和视觉表达，更适合当前用户任务；它牺牲了什么？

输入：通过检查的对象、流程和状态表；真实参考、采用理由与品牌规则；完全相同的文案、数据、状态和显示尺寸

1. 基于参考提出两个有实质差异的方向，如慢读行程与优先处理冲突；比较层级、密度、文字角色及品牌情绪。
2. 与负责人选定一个方向，写清采用与舍弃理由；将组件、内容和行为规格交给实现者，不让方向无限混合。
3. 由builder在指定副本实现比较、确认、结果和撤销这一条可运行路径；设计者检查实现是否保留了选定方向。

产物：两份同条件方案、一个方向决定、最小组件规则，以及builder交付的可打开路径。保存原版、运行方式和已知限制。

通过条件：能解释选定方向与任务的关系；状态与数据不靠装饰代替；builder提供可运行产物及操作入口后，进入完整Audit。若只有设计图，可先做视觉预审，但行为检查不得记通过。

常见坑：只换颜色就称探索；或一直产出漂亮静帧，没有人实现确认、取消和撤销。

### Audit｜先观察，再给问题排优先级

哪些问题有证据，最妨碍谁完成任务；哪些还没有检查？

输入：指定版本的可运行产物、设计稿和操作入口；体验约定、参考规则及本轮验收条件；检查环境、已有证据与明确的未验项

1. 按任务成功、UX、UI、无障碍四层检查；走主要流程及相关失败恢复，视觉检查使用同条件截图。
2. 每项记录位置、复现步骤、实际与预期、证据、影响、严重度和复查方法；推测与已验证问题分开。
3. 先标任务阻断和严重回归，再给出下一轮最值得修的一项；审查者只写报告，不同时修改被审版本。

产物：一份可定位的问题单与证据索引，注明检查范围、已通过、已发现、未验证及不适用的理由。

通过条件：优先问题能复现，或被清楚标为待验证假设；每项有负责人和复查方法。任务阻断不能被视觉高分抵消，未运行的检查不能算通过。

常见坑：用“高级感不足”或综合分代替证据；把自动扫描零报错、模型一致意见当作完整体验验收。

### Refine｜只处理一个主要问题，再回头检查

这次最小改动能解决什么，会影响哪些已有效的部分？

输入：负责人选定的问题及实际证据；允许改动的文件或画板、保留项和基线版本；设计者提供的最小改法、取舍与回归范围

1. 实施前写一句修改假设，必要时比较两个改法；由唯一写入者修改指定产物，设计者负责设计规格。
2. 只改该问题及必要关联元素，保存差异；涉及共享组件时记录受影响实例和页面。
3. 请审查者独立复查原问题并重走受影响状态，决定保留、回退或补证据，再把结果写入共享任务包。

产物：可回退的修改版、同条件前后对照、问题复查与回归结果，以及更新后的规则和未验项。

通过条件：原问题有实际复查结果，相关路径没有新阻断才保留；结果不明不能宣布改善。连续两轮同类改动无改善，或达到时间、额度、权限边界，就保存现场并回查假设。

常见坑：为了一个层级问题重写整个页面，或边修边加功能，导致改动的收益和回归都说不清。

### 上线前检查｜在真实交付条件下再走一遍

准备交付的这个版本，在哪些条件下能完成承诺；还有哪些阻断？

输入：准备交付的冻结版本和实际目标环境；完整任务路径、历史问题与未验清单；部署或演示范围、恢复办法和发布负责人

1. 在目标环境重走关键成功、错误与恢复路径，核对数据、重复操作、键盘焦点、窄屏和适用的辅助技术检查。
2. 复查字体、图片、组件状态、加载和错误文案；请目标用户独立完成任务，记录理解与犹豫，未开展则明确保留。
3. 整理可交付范围、阻断项、未覆盖环境及回退方式，由负责人决定发布、缩小演示范围或继续修复。

产物：针对指定版本与范围的交付结论：通过了什么、被什么阻断、什么未验证、由谁跟进，以及可运行产物与恢复点。

通过条件：该交付范围的核心任务阻断已修复并复查，关键检查有实际记录；有关键未验项时不能默认上线。教学演示与真实产品发布分别判断，不授予“世界级”或完整无障碍认证。

常见坑：把构建成功、截图好看或一次无报错运行当作上线结论，漏掉真实输入方式、数据与错误恢复。

## 二、共享任务包与交接

- `BRIEF.md`：用户、任务、范围、失败代价；协调者维护。
- `IA.md + STATES.md`：对象、导航、主路径、关键状态及动作契约。
- `REFERENCE-LOCK.md`：已选方向、来源、组件规则、tokens和禁区。
- `ACCEPTANCE.md`：从任务导出的通过条件与证据要求，实施前约定。
- `AUDIT.md + EVIDENCE/`：问题编号、严重度、复现、实际截图和测试记录。
- `DECISIONS.md + HANDOFF.md`：取舍、例外、当前版本和下一轮交接。

版本 / 本轮目标 / 已读输入 / 修改范围 / 产物位置 / 已验证及证据 / 未验证与风险 / 下一个Agent的具体任务

## 三、Prompt的最低结构

- 结果：谁在什么场景下，要完成哪个任务；成功与失败分别是什么。
- 边界：这一轮解决什么，不做什么，哪些业务事实与行为必须保留。
- 上下文：需求、研究、现有实现、参考与上轮问题的具体文件和版本。
- 体验契约：对象、导航、关键状态、动作后果、确认、取消和恢复方式。
- 设计方向：主参考、可借鉴规则、颜色语义、文字层级和明确禁区。
- 职责与权限：该Agent负责哪份输出、可改哪些文件、能调用哪些工具。
- 输出格式：产物在哪里，如何命名，报告必须包含哪些字段。
- 验证证据：检查哪个任务和状态，用什么方法，留下什么可复核证据。
- 修订与停止：失败回到哪一步；轮数、预算、阻塞、未知与交付条件。

## 四、角色Prompt模板

每份模板前补齐产品、用户任务、项目阶段、当前版本、输入路径、保留项、实际工具与权限、可写路径和轮数／预算。纯聊天入口由人传递材料与执行结果，不能把文字计划当实际操作。

### 总协调 Agent

把目标拆成能交接、能验收的任务。

```text
你是本项目的协调者。先读取输入材料，输出：已知事实、关键假设、缺失信息。不要把假设写成研究结论。

先明确用户任务与验收，再拆分职责：信息架构、方向探索、实现、独立审查、发布检查。每个子任务写清owner、依赖、允许修改的路径、输出文件、验收方式。依赖未满足的任务不得提前实现；参考研究和测试用例准备可以并行。

同一文件同一时间只有一个写入者。研究者交付带来源的观察；审查者只写问题和证据；你负责取舍与集成。每轮给新Agent一个短交接包，不让它猜测上文。

候选版本完成后，让独立审查者读取需求、验收契约和候选产物；不提供制作者的自评分。修订者按issue ID处理问题，并对受影响状态重新检查。

只在核心任务有证据通过、阻断问题清零、关键未知已处理时建议交付。达到轮数或预算上限仍不满足时，保留最后稳定版本并报告阻塞；不要强行宣布完成。

统一交接：版本 / 本轮目标 / 已读输入 / 修改范围 / 产物位置 / 已验证及证据 / 未验证与风险 / 下一个Agent的具体任务
```

### 信息架构 Agent

先确定对象、任务、状态和信息顺序。

```text
你负责信息架构，暂不制作高保真界面。

识别核心对象及关系；列出用户主要任务、入口、退出点、必要导航与内容优先级。用任务流程和状态表表达，而不只画站点地图。

对每个主要动作说明：起始状态、输入、发生的变化、用户看到的反馈、能否取消或撤回，以及失败恢复。区分界面状态与业务数据状态。

输出IA.md与STATES.md：关键对象、主路径、例外状态、每屏必须回答的问题、仍待验证的假设。把上线验收改写为可观察任务，例如“应用调整前草案不变，撤销后恢复原内容”。

保留任务包中的业务事实与不可变规则；不为填满页面增加未要求的功能。遇到范围矛盾，记录冲突与建议，由协调者决定。

统一交接：版本 / 本轮目标 / 已读输入 / 修改范围 / 产物位置 / 已验证及证据 / 未验证与风险 / 下一个Agent的具体任务
```

### 方向探索 Agent

用相同任务比较真正不同的方案。

```text
你负责探索两个有明确取舍的方向。先研究参考，记录来源、实际观察、采用原则和不采用部分。无法查看的素材不要称为已研究。

两版必须保持同一用户任务、业务状态、文案、数据和画面尺寸。让信息优先级、密度或交互结构形成有意义的差别，不只换配色。

根据当前任务提出两个有真实取舍的方向，例如一个降低操作负担，一个强化整体理解与掌控感；若不适合该业务，说明更合适的比较维度。为每版说明适用场景、收益、代价和下一步验证。

输出两版关键屏与一页REFERENCE-LOCK.md。协调者选定主方向后，固定其层级、组件与颜色语义，交给实现者完成一条可运行路径。新参考不得在后续轮次静默推翻已选方向。

统一交接：版本 / 本轮目标 / 已读输入 / 修改范围 / 产物位置 / 已验证及证据 / 未验证与风险 / 下一个Agent的具体任务
```

### 实现 Agent

把选定方向做成可操作的功能切片。

```text
你负责实现已选定的方向，不重新决定产品范围。先读取体验契约、参考约定、既有组件和本轮任务。

实现STATES中约定的最小完整路径：入口、关键决定与动作、结果反馈、失败恢复。确认与撤销按业务需要设计，不给每个低风险动作都增加确认。用明确的数据状态驱动界面，不让视觉标签替代实际逻辑。

只修改授权路径。若改共享组件，记录影响范围并检查引用处；保留基线与回退方式。加载、空内容、失败、取消等状态按任务约定实现，不伪装为已经接入真实服务。

输出可运行产物、修改文件列表、对应版本、检查命令或步骤、实际结果与未验项。附同条件截图和可复现路径；没有运行的检查一律写未验。

统一交接：版本 / 本轮目标 / 已读输入 / 修改范围 / 产物位置 / 已验证及证据 / 未验证与风险 / 下一个Agent的具体任务
```

### 独立 Audit Agent

找出阻止任务完成的问题，并提供证据。

```text
你是独立审查者，只输出审查报告，不修改实现。先读取用户任务、验收契约、参考约定和候选版本。

按五个维度审查：任务完成；信息架构与状态完整；视觉与内容一致；无障碍；工程与发布风险。每个问题包含：issue ID、严重度、位置或复现步骤、实际证据、对用户的影响、最小修正建议、复验方法。

本课严重度定义：P0会造成不可接受的损失或关键错误；P1阻止核心任务或造成重大误解；P2为局部质量问题；P3为可选打磨。具体影响以本项目约定为准。

先真正执行可用的检查。截图不能证明键盘、读屏、数据保存和错误恢复；启发式分析不等于真人测试。无法访问运行环境时写明未验范围。

不要给没有依据的综合分，也不要因为多个Agent都说好就标为通过。每条结论注明：观察事实、推测或未验证。最后列出阻断项、可延后项和需要补充的证据。

统一交接：版本 / 本轮目标 / 已读输入 / 修改范围 / 产物位置 / 已验证及证据 / 未验证与风险 / 下一个Agent的具体任务
```

### 修订 Agent

按问题编号修复，并证明没有造成回归。

```text
你负责修复已排序的审查问题。先读取候选版本与issue列表，确认每个问题能否复现；证据不足时先验证，不盲改。

这一轮选择影响最大的一个问题，或一组有共同根因的问题。写出最小修改计划与受影响状态，然后实施。保留用户任务、业务数据、参考方向与本轮禁止改动的部分。

输出issue ID→改动→验证证据→剩余风险的对应表。视觉前后图必须同任务、同状态、同内容、同尺寸。修了共享组件，复查所有相关状态；修了动作，复查确认、取消和撤回。

把修复交回独立审查者复验，修订者不得自行关闭问题。如果连续两轮没有实质改善，返回任务定义、信息架构或参考约定寻找根因。

统一交接：版本 / 本轮目标 / 已读输入 / 修改范围 / 产物位置 / 已验证及证据 / 未验证与风险 / 下一个Agent的具体任务
```

### 上线前检查 Agent

按验收范围判断可交付、限范围交付或阻塞。

```text
你负责上线前检查，不执行发布操作。锁定候选版本与目标环境，再核对验收契约。

重走核心与失败恢复路径，检查数据与文案、不同宽度与缩放、键盘与焦点、辅助技术、减少动态效果、相关性能和回滚方式。浏览器工具、自动化扫描与人工检查分别记录覆盖范围。

每项记录方法、环境、版本、实际结果和证据。未运行不能写通过；不适用需说明理由。构建成功、截图精美或自动化扫描无报错都不能单独作为完整交付依据。

输出RELEASE-REPORT.md：通过项、阻断项、未验项、已接受的局部风险、回退步骤、明确建议。核心任务有关键未知或未解决P0/P1时阻塞；达到轮数上限也不能自动放行。正式上线所需权限按当前授权处理。

统一交接：版本 / 本轮目标 / 已读输入 / 修改范围 / 产物位置 / 已验证及证据 / 未验证与风险 / 下一个Agent的具体任务
```

适用时机：业务流程已经明确，需要把同一份任务和内容做成有辨识度的网页或交互原型。

输入：用户任务、固定业务文案、参考图及取舍说明、品牌约束、技术栈、目标屏幕尺寸。

产物：可运行的界面代码，以及能解释排版、层级和交互选择的设计说明。

边界：视觉指导不等于用户研究或可用性验收。保留产品事实、现有设计系统和平台惯例；不要靠新增业务内容制造设计差异。

平台：方法与上下文可迁移到其他模型；自动加载 Skill 取决于宿主支持。纯聊天可参考其方法，但不能因此获得文件修改、运行或截图能力。

产物：针对目标页面的设计判断、具体问题清单，以及保持业务含义的界面修订。

### Human Review · 人工批注回传（Skill）

把 HTML、Markdown 或本地页面交给人直接编辑和批注，再把整批反馈交回 Agent 处理。它收集反馈，不负责自动把文字改自然。

输入：待评审文件或本地页面、这轮需要人判断的问题，以及可运行的本地工具和浏览器。

产物：与页面位置对应的批注和编辑批次，以及据此修改后的源文件。

边界：需要人参与，不能当作无人值守的自动评审。普通 HTML 的直接编辑可能已自动保存；修改前重新读取文件，避免覆盖人的改动。

平台：Skill 包含 CLI 工作流；不同宿主等待反馈的方式不同，任务结束后不保证自动唤醒。它不是通用 MCP，也不是网页聊天粘贴即可启用的插件。

要求在声称完成前明确证据、执行相应检查、读取结果，再判断结论是否成立。特别适合防止把子 Agent 的自述当成验收。

Git：https://github.com/obra/superpowers

产物：有证据支撑的完成项、未通过项和阻塞项；检查范围与结论范围保持一致。

边界：检查通过只能支持它实际覆盖的内容。静态检查不能替代现场播放；工具被阻塞时应如实记未验证，不能为取得证据绕过限制。

平台：这套验收方法可以直接用于任何模型；Skill 安装属于宿主能力，真正执行检查还需要对应工具。按改动选择有效检查，避免机械扩大测试范围。

## 六、上线前检查

### 主任务兑现

方法：从清楚起点实际操作到可确认结果，覆盖声明支持的主要路径。

证据：带版本的操作录屏或逐步结果记录。

阻断条件：主任务无法完成、结果错误或宣传承诺无对应能力。

范围：本次声明交付的关键任务；不把一条路径通过推广为所有功能通过。

### 异常与恢复

方法：触发关键失败、离线/超时、重试、取消与返回，按业务相关性选择。

证据：状态表与实际转换记录。

阻断条件：失败后无可行下一步、恢复破坏输入、未完成就显示成功。

范围：实际存在的状态；模拟明确标注，不声称已验证真实设备/服务。

### 事实与跨端一致

方法：核对金额/单位/对象/更新时间等关键事实；对比同一状态的多端呈现。

证据：同一数据样本及各端截图，事实来源说明。

阻断条件：关键数据含义错误，旧信息被表述为实时，跨端矛盾导致错误行动。

范围：按产品真实风险选字段；例如植物读数24%不能自动推出必须浇水。

### 视觉与内容回归

方法：用真实长度内容逐屏检查关键断点；对照既有设计规则。

证据：目标窗口截图、长内容样例、组件规则差异。

阻断条件：主要内容/动作被遮挡或截断，视觉修改破坏既有功能。

范围：约定设备与窗口；不要求所有装饰意见都成为发布阻断。

### 文字对比

方法：测量实际文字前景与背景；一般文字至少4.5:1，大号文字至少3:1，按适用定义及例外判断。

证据：元素、颜色、字号/字重、精确比率及例外理由。

阻断条件：适用且影响声明范围的文字未达已承诺标准，尤其关键说明无法辨读。

范围：Web WCAG2.2 1.4.3教学基线；大号文字为18pt或14pt粗体，不将所有品牌文字豁免泛化。

### 键盘与焦点

方法：不用鼠标走关键路径；检查顺序、可见焦点、无陷阱及固定头部/浮层遮挡。

证据：按键顺序、焦点截图、实际不能到达的控件。

阻断条件：关键动作键盘不可达、焦点丢失或被困、无法知道当前位置。

范围：目标Web键盘交互；2.4.11最低要求关注点不被作者内容完全遮住，教学建议进一步保持清楚可见。

### 控件语义与模态框

方法：检查名称/角色；若有modal，验证打开后焦点在框内、Tab循环、Esc关闭及合理返回；核查背景非活动。

证据：可访问性树、键盘记录、屏幕阅读器抽查记录。

阻断条件：重要控件无可理解名称，模态行为使用户无法完成或退出任务。

范围：使用modal时适用；APG是实现模式指导，标ARIA不能代替实际行为。

### 目标尺寸

方法：量取指针目标；以至少24×24 CSS像素或符合间距等规定例外检查，并实测操作。

证据：目标边界/间距与例外说明。

阻断条件：关键目标不满足已承诺标准且无适用例外，或实际操作产生严重误触。

范围：Web WCAG2.2 2.5.8；不是所有设备一律24像素，也不是所有小文字链接必然失败。

### 缩放与减少动效

方法：在约定窄屏和放大条件检查阅读/操作；启用减少动态效果设置，验证仍能理解状态。

证据：窗口/缩放比例、设置、截图和操作记录。

阻断条件：关键内容或动作不可达，动画成为唯一状态信息或阻断任务。

范围：这是课堂关键抽查，不凭一次200%放大宣称满足全部重排标准。

### 构建与资源

方法：按项目运行必要构建/测试，检查入口、资源、链接及控制台；只读报告与实际执行分开。

证据：构建标识、测试输出、坏链接/失败资源清单。

阻断条件：无法启动、核心资源失败、未解决异常影响关键功能。

范围：按改动风险选检查；没有执行工具时标未验证，不自动生成通过日志。

### 发布权限与数据边界

方法：核对目标环境、授权、测试数据、公开内容及密钥；确认未把本地预览当公开发布。

证据：发布目标与批准范围、数据清单、配置检查结果。

阻断条件：未授权上线、错误环境、秘密或真实敏感数据暴露、超出用户授权的外部动作。

范围：已有明确授权可执行对应发布；不重复制造确认流程，但新越界动作必须停止。

### 备援与可追溯交接

方法：打开最终产物与同版本备援；确认回退入口、未完成项、负责人和下一步。

证据：实际存在的文件/URL、播放记录、版本对应、交接说明。

阻断条件：交付物打不开、唯一关键演示依赖失效且无可行备援，或关键未知未披露。

范围：演示与正式发布分别记录；未录制的备援只能列待办，不算完成。

## 七、停止与交付

最多三轮是教学节奏默认值，不是质量证明，也不是达到轮次就必须发布。

所有适用关键门槛有当前版本证据；无P0/P1及影响发布承诺的关键未知；剩余低风险项已记录负责人和处理计划。

三轮后仍有P0/P1或关键未知，停止该范围的交付/发布承诺，输出阻断证据和下一步；可交研究报告或明确标记的未完成原型，但不称验收通过。

## 八、常见坑

### 一开始就让AI做完整首页，没有具体任务。

页面很多，却无法判断用户的关键决定是否得到支持。

先完成Brief，用起点、决定、结果和恢复写清一条路径，再安排制作。

### 探索两版时连数据、文案和业务状态也一起换掉。

分不清偏好来自视觉、内容，还是任务本身变了；对照无法指导选择。

固定任务、状态、内容和尺寸，只比较一个主要设计方向，写明收益与代价。

### 几个Agent同时改同一页、组件或文件。

互相覆盖，组件规则漂移，最终版本无法追溯。

按产物分配唯一写入者；研究和审查先只读，负责人统一合并，并保留回退点。

### 共享上下文只靠长聊天，新Agent根据记忆接手。

上轮假设被当成事实，已否决方向回流，关键状态被遗漏。

维护一页当前任务包：版本、规则、决定、问题、未验项及本轮范围；接手先复述，再工作。

### Audit只给总分或“看起来很高级”，自动扫描无错误就称通过。

严重阻断被平均分掩盖，已检查与未检查混在一起。

每项写位置、复现、证据、影响与复查；先处理阻断，结论限定版本和范围。

### 一次Refine重写结构、视觉、文案，还加了新功能。

无法解释哪项改动有用，也容易破坏原来能工作的路径。

每轮只检验一个主要假设及必要关联改动；保留数据和原版本，复查受影响的状态。

### 让AI扮演五个用户，再把意见写成用户测试结果。

风险猜测变成虚构证据，团队误以为用户已经理解或喜欢方案。

将AI意见标为检查线索；邀请目标用户独立完成任务，记录提示、犹豫、错误与解释。

### 夜间任务只有“继续优化”，连续改动却没有退出条件。

耗费额度、反复改同类问题，早晨仍不知道什么版本可以交付。

限定问题数、时间、费用和写入范围；连续两轮无改善回查假设，达到边界保存现场，关键未验项不计通过。

## 九、多Agent新增风险

### 共识幻觉

多人同意可能只是重复同一推断。

策略：先独立出报告，再对照证据；负责人指定一位寻找反例；保留不同意见。

证据：独立报告时间、反例与最终决策理由。

### 同一上下文偏见

任务包遗漏让所有Agent一起忽略同一用户或失败场景。

策略：共同事实保持一致，但分配不同检查任务与数据样本；补真人试用或外部证据，标出未知。

证据：覆盖矩阵、不同样本、假设清单。

### 文件冲突

同时写同一文件覆盖成果或组合成不可运行版本。

策略：报告各写独立路径；唯一实现者合并；需要并行实现时按文件/分支划界并做集成检查。

证据：写入分工、变更差异、集成结果。

### 丢失约束

长对话或交接后忘记关键限制。

策略：固定BRIEF/STATES/DESIGN版本；每轮重述不可改变项，产物关联版本。

证据：输入版本和约束复核记录。

### 机械审计

只检查清单与截图，没有真的走任务。

策略：先操作关键任务再跑量表；自动扫描与人工观察分栏；不以工具零告警代表体验良好。

证据：实际操作记录、工具范围及未测项。

### 无限循环

泛泛要求再高级一点，反复生成没有收敛。

策略：每轮最多三项具体改动，每项附验收；修复无新证据就停止追加装饰并回到决策。

证据：轮次目标、前后差异、退出理由。

### 成本与预算

并发、长输出与重试放大耗时/消耗。

策略：预设可执行的调用/时长/费用上限、失败重试次数；硬限制依平台能力设置，不把Prompt当计费闸门。

证据：实际资源记录、限额配置或无法强制限制的说明。

### 越权上线

Agent把设计完成自行解释为可以部署、发送或处理真实资产。

策略：区分制作、预览、发布；按现有授权执行，对新增越界动作停止并说明所需授权。

证据：授权范围、目标环境与外部动作记录。
